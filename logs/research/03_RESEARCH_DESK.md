# 研究台第一階段（D-256）：新聞室改成投資研究

> 2026-10-21。這是 0-A「把現有 AI Agents 的報導方向與內容流程轉成投資研究」的第一階段改造說明。
> 程式在分支 `worktree-research-r1`（基於 `a2d9f0e`），沒有新增資料表或遷移。
> 開發紀錄：`logs/devlog/09_RESEARCH_DESK.md`；決策：D-256。

## 一、改了什麼

### 1. 選題與排序

總編（`agents/editor_in_chief.py`）的候選題材，排序依據從「題材分數」改為**研究價值**（`research.research_value`）：

```
研究價值 = 0.5 × 題材分數（多來源、新鮮度、來源可信度）
         + 0.3（點名追蹤中的上市公司）
         + 0.2（屬於重大事件：財報、財測、訂單與資本支出、產品製程、政策、公司行動、訴訟）
```

每個候選都附上標記，例如：

- `companies: 台積電(2330), 輝達(NVDA)`
- `events: earnings, guidance`

總編另外會看到追蹤股票清單，以及每檔最近一次個股研究、策略研究的日期，用來決定今天該寫什麼。

D-253 的題材比例照舊：AI 供應鏈至少 90%，加密貨幣最多 1%。

### 2. 文章格式與分類

格式記在 `stories.seed.format`，四個職位都從這裡讀。所以流程模板、審批、發布、題材比例的計算都沒有改。

| 格式 | 由誰發起 | 網站分類 | 內容 |
|---|---|---|---|
| `news` | 總編（`commission_story`，格式選 news） | 依來源（台股、美股、AI…） | 和以前一樣的新聞報導 |
| `research_brief` 投資研究快報 | 總編（`commission_story`）；**點名追蹤公司的題材預設就是這種** | 依來源 | 事件重點、影響哪些公司（傳導路徑）、多空論點、主要風險、後續觀察 |
| `company_report` 個股研究 | 總編（`commission_company_report`），每天最多 1 篇，同一公司 30 天 1 篇，不寫 ETF | **個股研究**（新分頁） | 公司概況、營運與財務、估值與市場預期、多方論點、空方論點、主要風險、後續觀察、資料限制 |
| `strategy_study` 策略研究 | 總編（`commission_strategy_study`），每天最多 1 篇，同一檔加同一規則 90 天 1 篇 | **策略研究**（新分頁） | 策略規則、資料與成本假設、樣本內結果、樣本外結果、限制與失效條件 |

前台新增「個股研究」「策略研究」兩個分頁，放在「AI 科技」之後。

### 3. 新聞轉研究的生成流程（每個職位多了什麼）

| 職位 | 改動 |
|---|---|
| 研究員 | 依格式拿到工作說明，以及兩個本站自算的紀錄工具：`market_snapshot`（個股股價數據）、`run_backtest`（策略回測）。個股研究**必須**附 `market_snapshot`，策略研究**必須**附 `run_backtest`（validator 檢查） |
| 分析師 | 輸出多了以下欄位：`bull_claim_ids`、`bear_claim_ids`、`risk_claim_ids`（多方、空方、風險）；`inferences`（推論：每條必須列出依據的論點，且不能含建議或預測用語）；`data_gaps`（缺少的資料）。各格式的最低數量見下節 |
| 寫手 | 拿到格式大綱、多空與風險論點、推論（必須寫成「推論：…」）、資料缺口。`write_draft` 會擋下缺少段落標題的稿件，也會擋下「目前符合進場條件」這類說法 |
| 編輯、總編終審、審批 | 不變（避免和尚未合併的 d254「簡化審稿」衝突） |

### 4. 品質檢查：來源、事實、推論、風險

| 檢查 | 在哪裡 | 規則 |
|---|---|---|
| 來源 | 研究員 validator（既有規則加上新規則） | 至少 2 個來源、來自 2 個以上網站；個股研究要有股價數據紀錄，策略研究要有回測紀錄 |
| 事實 | 既有 fact-check | 數字必須出現在證據的引文中，所以本站計算的數字也只能透過本站紀錄的證據進入文章 |
| 推論 | 分析師 validator（`research_sides`） | 推論必須列出依據的論點；含建議、預測、本站立場或臆測動機的用語會被擋下 |
| 多空與風險 | `research.stance_problems` | 研究快報：至少 1 個多方，加上 1 個空方或風險。個股研究：多方、空方、風險各至少 2 個。策略研究：至少 1 個風險 |
| 結構 | `write_draft`（`research.draft_problems`） | 每種格式的段落標題在每個語言都要齊全 |
| 不給訊號 | `write_draft` | 研究文章不能說某規則「目前、今天」觸發；只能寫歷史表現 |
| 不給建議 | 既有 `newsroom.no_advice`（D-035） | 照舊：不給買賣建議、不做本站預測；多空並列、不下結論 |

### 5. 本站自算的紀錄（不靠 LLM 判斷）

- **`snapshot.py`**：讀取個股頁使用的日線，計算最新收盤價、52 週高低、1、3、6、12 個月報酬、MA20／60／200、RSI(14)、60 日年化波動度、量比。最後寫明「本站沒有財報、EPS、估值倍數、股利、分析師預估」，讓文章可以引用這段話來說明資料缺口。
- **`backtest.py`**：三條固定規則，參數在看到結果前就已固定，不針對個股調整：
  - 20 日區間突破；
  - 多頭趨勢回檔轉強；
  - 區間均值回歸。

  回測方式：
  - 以收盤價判斷訊號，次一交易日開盤成交；
  - 只做多、一次一個部位；
  - 前 70% 為樣本內、後 30% 為樣本外；
  - 計入成本：台股手續費 0.1425% 與證交稅 0.3%（ETF 為 0.1%），兩個市場都假設 0.05% 滑價；
  - 交易少於 20 筆時，紀錄會註明統計可信度低。

## 四、獨立風險清單

### 4.1 本次可直接實作（已實作）
- 公開資訊分析：研究快報、個股研究。只陳述事實與他人具名的看法，多空並列、不下結論。
- 投資教育：策略規則說明。
- 歷史策略研究：由程式計算，只呈現歷史結果、成本與限制，不給「現在符合」的訊號。

### 4.2 需要確認資料授權的行情功能（不擋本階段，另列）
- `market_snapshot`、`run_backtest` 使用已存的日線。美股資料來自 Tiingo，免費方案依 2026-10-06 的條款**禁止持久儲存，也禁止公開顯示資料圖表**。條款允許回測的彙總統計作為衍生產品，但前提是付費方案（詳見 P0-2 文件）。
- 台股資料來自證交所網站端點，網站條款禁止未經同意的自動下載。

**替代方案**：文章只呈現統計數字，不放價格圖，可以降低「顯示原始資料」的疑慮，但不能解決儲存與擷取的問題。授權問題仍待處理。

### 4.3 上線前需要專業審查（本階段沒有做）
- 對個人的買賣指令、個人化目標價、個人化資產配置建議（屬於 R5，一律不做）。
- 每日掃描並公開列出「今天符合條件的股票」（S4）。
- 個股策略卡上的「現在進場條件」（S3）。`write_draft` 已擋下這類說法。
- 研究內容放在付費或鯨幣後面：D-224 研究計費與 VIP 文章都要等律師回答「間接報酬」的問題。

### 4.4 實作上的風險
- **審稿流程衝突**：d254「簡化審稿」尚未合併，它改動了 `workflow.py`、`editor.py`、`review.py`。本階段刻意不碰這三個檔案；合併時兩邊都要重跑測試。
- **新 validator 被擋就會重試，增加模型費用**：研究快報要求多空與風險、每種格式要求段落標題，模型第一次沒照做就會修正或重試。建議上線後一週看 `newsroom_waste.py` 與審批報表。
- **長文被截斷**：個股研究的雙語稿件較長，寫手的 `max_output_tokens`（8192）可能不夠。已把篇幅定為每個語言 12–18 段；如果出現截斷，再調高上限。
- **新分頁先是空的**：「個股研究」「策略研究」要等第一篇發布後才有內容。
- **部署順序**：舊版 API 不認得 `section=research`、`strategy`。如果前端（Vercel）比 API（Render）先上線，在 API 完成部署前點新分頁會出現錯誤頁。本機用新前端接正式 API 預覽時，實際看到 422。首頁與其他分頁不受影響。建議先確認 Render 部署完成，再讓前端上線；或接受這幾分鐘的空窗。
